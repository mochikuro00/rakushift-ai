## 1. サービス紹介リーフレット（営業用A4 PDF）

```

- イレギュラーシフト（人員不足警告）の視覚化

Step 3: スタッフ情報を登録

【トーン】専門的すぎず、店長・オーナーが読んで「使ってみたい」と思える親しみやすい文体。
【出力形式】A4両面のテキスト原稿（表面: キャッチ＋特長＋業種、裏面: 料金＋導入の流れ＋FAQ）
```

## 2. 操作マニュアル（導入後のお客様向け）

```
あなたはSaaSの操作マニュアルを作成するテクニカルライターです。
以下の情報をもとに、「ラクシフトAI」の操作マニュアルを作成してください。
対象読者は飲食店や小売店の店長・マネージャーで、ITリテラシーは高くありません。

【サービス概要】
ラクシフトAIは、AIがシフトを自動生成するクラウドサービスです。

【ログイン方法】
- 店舗ログイン画面から契約IDとパスワードを入力してログイン
- 管理者ID「admin」でログインするとAIシフト作成等の全機能が利用可能

【スタッフ設定の重要機能】
1. 希望時間の考慮トグル
   - スタッフの編集画面で「このスタッフの希望時間をシフトに考慮する」のON/OFFが可能。
   - アルバイトなどはONに。社員や店長など、店舗の状況に合わせて柔軟に入ってほしい人はOFFに設定します。
2. 週の最低出勤日数
   - スタッフごとに「週に最低◯日出勤」を保証する設定が可能です。

【AIシフト作成とイレギュラー表示】
1. 画面右上の「AIシフト作成」ボタンをクリック
2. 作成範囲を選択して「作成を実行」
3. プレビュー画面が表示されます。
   - 【重要】赤斜線の太枠になっているシフトは「イレギュラーシフト」です。店舗の人員が不足しているため、AIがやむを得ず割り当てた箇所です。必ず店長が目視で確認し、必要に応じて修正してください。
4. 内容を確認して「確定して保存」をクリック。

【出力形式】章立てされたマニュアル文書。見出し・箇条書き・注意事項を使い、読みやすく構成。
【トーン】丁寧語。専門用語は避け、「〜してください」「〜が表示されます」のような指示形式。
```

## 4. 投資家/パートナー向けピッチ資料

```
あなたはスタートアップのピッチ資料を作成するコンサルタントです。
「ラクシフトAI」の事業概要をまとめたピッチデック用テキストを作成してください。

【会社】リンクデザイン株式会社
【サービス】ラクシフトAI - AIシフト自動生成SaaS
【フェーズ】商用リリース済み、テナントオンボーディング開始

【技術スタック】
- フロントエンド: HTML/JS + Tailwind CSS（Cloudflare Pages配信）
- バックエンド: Python FastAPI + PuLP（MILP最適化エンジン）
- データベース: Supabase（PostgreSQL + RLS + RPC）
- 決済: Stripe（サブスクリプション自動処理）

【競合優位性（AIアルゴリズム）】
1. MILP (混合整数線形計画問題) エンジン
   - 単なるLLM生成ではなく、PuLPを用いた厳密な数理最適化。労働基準法を「絶対制約（Hard Constraints）」として数式化し、違反を100%防止。
2. 階層型ペナルティ制約（Soft Constraints）
   - 「店舗の必要人数」と「スタッフの希望時間」「最低出勤日数」を天秤にかけ、不足分や過剰分をペナルティスコアとして最小化。
3. 人員不足への自動対応（Greedy Fallback）
   - どうしてもシフトが埋まらない場合、計算不能(Infeasible)で停止せず、「イレギュラーシフト（is_irregular）」フラグを立てて強制的に配置し、UI上で赤斜線としてマネージャーに警告を出す実践的フェイルセーフを実装。
4. スタッフ優先度＆社員タグ
   - 社員は希望時間を無視して穴埋めに回る設計など、現場のオペレーションに即した変数制御。

【出力形式】各スライドのタイトル + 箇条書き内容 + スピーカーノート
```

## 6. AIアルゴリズム技術資料（エンジニア・アライアンス向け）

```
あなたはAIソリューションアーキテクトです。
以下のアルゴリズム詳細をもとに、「ラクシフトAI」のコアエンジン技術仕様書（ホワイトペーパー）の構成と原稿を作成してください。

【エンジン概要】
- フレームワーク: PuLP (Python) + CBC Solver
- 方式: 混合整数線形計画問題 (MILP) によるスケジューリング
- 処理フロー:
  1. 需要パターンの時間粒度へのマッピング (15分〜1時間単位)
  2. スタッフ条件（役職、スキル、希望時間、NG日、最低出勤日数）の変数化
  3. 制約式の定義（ハード制約・ソフト制約）
  4. 目的関数（ペナルティ最小化）の設定と最適化計算

【ハード制約（絶対厳守）】
- 労働基準法第32条: 1日8時間、週40時間を超えない
- 労働基準法第34条: 実働6時間超で45分、8時間超で60分の休憩付与
- 労働基準法第35条: 連続勤務を6日以内（週1日の休日）に制限
- インターバル規制: 退勤から翌日の出勤まで最低10時間を確保
- NG日・承認済みの休みの確実な除外

【ソフト制約（ペナルティによる最適化）】
- 店舗の必要人員数との乖離（不足・過剰の最小化）
- スタッフの「優先度（priority）」に基づくシフト割り当て比重
- スタッフの「週の最低出勤日数（min_days_week）」の保証
- スタッフごとの「希望出勤時間・退勤時間」への適合

【実践的フェイルセーフ（Infeasible回避）】
- 需要に対して人員が絶望的に足りない場合でも、ソルバーが計算エラーで停止しない設計。
- 不足スロットを特定し、AIが「イレギュラーシフト（is_irregular = True）」として強制的にスタッフを割り当て、不足分を補う。
- フロントエンド側でイレギュラーフラグを検知し、赤色斜線の太枠（UI警告）として描画することで、管理者に人的な判断・修正を促す「ヒューマン・イン・ザ・ループ」を実現。

【トーン】技術的で説得力のある論理的な文体。アルゴリズムがいかに「現場の実態（人員不足など）」に強く、かつ「法律」を厳守する安全なシステムであるかを強調。
【出力形式】Markdown形式のホワイトペーパー
```
