あなたはフルスタックエンジニアです。私の【サービス名】向けに「運営管理者コンソール」を作ってください。運営（サービス提供者）が全顧客・契約・売上・お知らせを一元管理するための管理画面です。技術構成と要件を文章で説明するので、その通りに実装してください。

まず全体の考え方です。この管理画面はデータベースに Supabase（PostgreSQL）を使い、画面は admin.html という一枚のHTMLファイルだけで作ります。ビルドツールは使わず、素のJavaScriptと、CDN読み込みのTailwind CSSでスタイルを当ててください。外部SaaS連携や重い集計、メール送信が必要な部分だけ、別途 Python の FastAPI で小さな補助APIを用意します。最重要の設計思想は「業務ロジックと権限判定をすべてデータベース側の関数に集約し、フロントエンドは一切信用しない」ことです。画面はデータベースの関数を呼んで結果を表示するだけの薄い存在にしてください。こうすることで、静的なHTML一枚でも安全な管理コンソールになります。

次に認証と権限のモデルです。ここがこのシステムの核なので厳密に作ってください。運営管理者を保存するテーブルを用意し、ログインIDと名前、そしてパスワードはbcryptでハッシュ化して保存します。平文やSHAでの保存は禁止です。すべてのログイン利用者に共通のセッションテーブルも用意し、そこにセッションID、ロール名、利用者ID、有効期限を持たせます。ログイン処理はデータベースの関数として実装し、ログインIDとパスワードを受け取ってbcryptで照合し、成功したらセッションテーブルにロール名「運営管理者」で有効期限7日のセッションを1件作成し、そのセッションIDを呼び出し元に返してください。

画面側はログインが成功したら、返ってきたセッションIDをブラウザのセッションストレージに保存します。そして以降データベースの関数を呼ぶすべての通信で、そのセッションIDをHTTPリクエストヘッダに毎回付けて送ってください。データベース側にはヘッダからセッションIDを取り出す関数と、そのセッションIDから現在のロールを引く関数を用意します。そして業務用の関数はすべて、実行の冒頭で現在のロールを確認し、運営管理者でなければ例外を投げてアクセスを拒否するようにしてください。この仕組みにより、たとえフロントエンドのコードを改ざんされても、権限判定はデータベース内で毎回やり直されるため、権限の昇格ができません。これがサーバーを真実とする設計です。

データベースのセキュリティも徹底してください。すべてのテーブルで行レベルセキュリティ（RLS）を有効にし、テーブルへの直接の読み書きは原則すべて拒否します。データの操作は、必ず権限チェック付きのデータベース関数（定義者権限で動く関数）を通してのみ行えるようにしてください。加えて、ログインの試行履歴を記録するテーブルと、関数内で起きたエラーを記録するテーブルも用意し、監査できるようにします。

続いて画面の構成です。ログイン画面と、ログイン後のダッシュボードを作ります。ダッシュボードは複数のタブで構成し、タブをクリックすると対応する内容だけが表示されるようにしてください。各タブの中身は、そのタブが開かれたときに対応するデータ取得関数を呼んで一覧を描画する方式にします。用意してほしいタブは次の通りです。

一つ目は契約テナント管理です。契約している顧客（店舗や会社）の一覧を表示し、新規発行、利用停止、利用再開、データ削除、契約情報の編集ができるようにします。ここで契約の状態は必ず二つの軸で管理してください。一つは課金の状態（契約中か解約済みかなど、決済側の状態）で、もう一つはアクセスの状態（利用可能か停止中か）です。この二軸を分けることで、「解約されても一定期間はデータを保持したまま利用停止にし、猶予期間を過ぎたら削除する」という運用が表現できます。

二つ目は顧客情報の台帳です。契約中の顧客、まだ問い合わせ段階の見込み客、解約手続き中の顧客を一つの一覧に統合して表示します。さらに、それぞれの顧客がどの請求方法かで分類し、タブやフィルタで切り替えて見られるようにしてください。分類は、決済サービスの顧客IDを持っていれば「カード自動決済」、特定の代理店プランなら「代理店経由」、それ以外の手動発行なら「請求書払い」とします。この分類の判定ロジックは自分のサービスの区分に合わせて調整してください。

三つ目は支払い管理で、決済サービスから入金済みと未収の一覧を取得して表示します。四つ目は事業収益で、毎月の売上、プランごとの契約数と金額の集計、そして顧客ごとの収益一覧を表示します。この顧客別一覧には、先ほどの請求方法の切り替えタブと、各列（名前、プラン、金額、状態、登録日など）でのクリックによる昇順降順の並べ替えを付けてください。

そのほか、自分のサービスに必要なタブを追加します。たとえば、運営配下に中間管理者を置く場合はその管理者の発行と担当範囲の設定、代理店や紹介者がいる場合はその登録と実績管理、見込み客からの問い合わせ管理、全顧客への一斉お知らせ配信、そして運営手順を書いた静的なマニュアルなどです。必要なものだけ選んで実装してください。

画面を作るときの注意です。データベースから取得した文字列を画面に表示する際は、必ずエスケープ処理をしてクロスサイトスクリプティングを防いでください。通常のテキストとして表示する場合と、ボタンのクリック処理などJavaScriptの文字列として埋め込む場合とでは、必要なエスケープが異なるので、用途に応じて二種類を使い分けてください。

補助APIについてです。データベースの関数では扱いにくい処理、つまり外部の決済サービスや外部SaaSとの連携、複数ソースを跨ぐ重い集計、メール送信などだけを、FastAPIの小さなエンドポイントとして実装します。補助APIも、画面から送られてくるセッションIDを受け取り、データベース側でロールを再確認してから処理するか、サーバー間の秘密鍵で保護してください。認証なしで動くエンドポイントを作ってはいけません。

最後に運用の自動化です。定期実行の仕組み（cronなど）を使って、有効期限の切れたセッションの削除、古いログイン試行履歴の削除、古いエラーログの削除、保持期間を過ぎたデータの削除、そして解約発効日を過ぎた契約を自動的に利用停止にする処理を、それぞれ定期実行してください。

以上の要件で、まずデータベースのテーブルと関数、次にログインを含むadmin.html、最後に補助APIの順で実装し、それぞれ動作確認してから進めてください。不明な点は推測せず私に確認してください。
