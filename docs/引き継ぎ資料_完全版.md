## 1. サービス概要

**ラクシフトAI** は、飲食・小売・医療介護店舗向けのAIシフト自動生成SaaS。

- **Python数理最適化(PuLP/MILP)** でベースシフトを生成（3段階フォールバック）
- **Gemini AI** が労働基準法チェック・最終監査
- **プレビュー機能** で生成結果を確認してから保存
- マルチテナント対応（1契約ID = 1店舗）
- Stripe決済によるサブスクリプション課金

**URL:**
- 本体: https://rakushift-ai.pages.dev
- 管理画面: https://rakushift-ai.pages.dev/admin
- GitHub: https://github.com/mochikuro00/rakushift-ai

## 10. AIシフト生成の仕組み

### フロー（プレビュー対応版）
```
「AIシフト作成」ボタン → 作成範囲選択
  ↓
1. /check — 人員充足チェック
  ↓
2. /generate — PuLP MILP最適化 → Gemini AI監査
  ↓
3. ★プレビューモーダル表示（統計サマリー＋日別シフト表）
  ↓
4. ユーザーが「確定して保存」→ DB保存
  ↓
5. AI診断（バックグラウンド実行）
```

### 制約一覧 (v3.7.31 現在)

**HARD 制約（絶対遵守 / 違反すれば Infeasible）**
- 1日1シフト
- 連続6日上限（労基法35条）
- 週40時間以内（労基法32条）
- 勤務間インターバル 10時間以上
- 6h超→45分休憩、8h超→60分休憩（労基法34条）
- 週/月最低出勤日数（v3.7.18 以降 SOFT 化されたが、UI トグルで HARD 復帰可）

**SOFT 制約（ペナルティで緩和可）**

| 種別 | ペナルティ / ボーナス | 説明 |
|------|---------------------|------|
| カバレッジ過剰 (OVER) | **20M** | v3.7.28 で 8M → 20M に再強化 (過剰絶対回避)。COVERAGE_OVER_DAY / COVERAGE_OVER_SLOT 共通 |
| 社員1名以上常駐 (OPEN_CLOSE_NO_EMP) | 10M | 月給+店長カテゴリの社員が常時1名以上いる事を要求 |
| 承認済み出勤希望 (approved) | -10M | v3.7.30 で HARD → SOFT 化。配置時ボーナス、過剰時 (20M) は諦め |
| カバレッジ不足 (UNDER) | 5M | 必要人員に満たない |
| 希望シフト EXACT 一致 (pending) | -3M | ボーナス |
| 希望シフト CLOSE 一致 | -2M | ボーナス |
| 希望シフト BASE 一致 | -1.5M | ボーナス |
| 担当ポジション不足 | 3M | ホール/キッチン等の必要人数 |
| OJT 新人×メンター帯同 | 500k | v3.7.18: 3M → 500k に弱化 |
| SHIFT_COST | 100k | シフト1本のベースコスト |
| 必須ペア (req_pairs) | 100k | 設定ペアの同時出勤 |
| 離職防止 (全員週1配置) | 50k | v3.7.21: HARD → SOFT 化 |
| 月給スタッフ不在ペナルティ | **30k** | v3.7.28 で復活 (月給スタッフ優先配置、弱い形で) |
| min_days_week / min_days_month | **30k** | v3.7.29 で 200k → 30k に弱化 (希望事項扱い) |
| 公平性偏差 | 10k | 出勤回数のばらつき |
| PRIORITY_HIGH ボーナス | -10k | 高優先度スタッフを優先 |
| 時給スタッフ控え目配置 | **5k** | v3.7.29 で 15k → 5k に弱化。通常時は時給を控え目に |
| スポット帯時給投入 | **0** | v3.7.28 追加。time_staff_req≥2 のスロットに重なる時間帯は時給スタッフも積極投入 |
| CONTRACT_REGULAR ボーナス | -2k | 正社員契約を優先 |
| 常時希望時間帯 (pref_start_wd/we) | -1k〜 | v3.7.13 で追加された MILP ボーナス |
| メンター主担当マッチング | -1k | メンター指定スタッフを担当ペアに |

**評価ランク D の特例**: evaluation=="D" のスタッフは rookie 扱いから除外され、OJT メンター帯同制約の対象外 (v3.7.23)。

**ペナルティ階層 (簡易図解 v3.7.31)**:
```
COVERAGE_OVER       20M ← 過剰絶対回避 (最強)
OPEN_CLOSE_NO_EMP   10M
承認済み希望        10M ← 通常時は確実に配置、過剰時は諦め
COVERAGE_UNDER       5M
PREFERENCE_EXACT    -3M
SHIFT_COST         100k
月給不在            30k ← 月給優先
min_days SOFT       30k ← 希望事項
時給通常コスト        5k
時給スポット投入       0
```

**解けない場合（Infeasible時）のフェイルセーフ:** 
MILP (HARD+SOFT) → Infeasible → SOFT 一部緩和して再求解 → 貪欲法（Greedy）フォールバック
※v3.7.31 で Greedy の過剰回避を厳格化 (`>= max_slot_req_day` でぴったり停止)。それでも不足する場合は `is_irregular=True` をセットして強制配置し、UIで赤枠警告（Human-in-the-loop設計）。

## 18. 変更履歴 (v3.7.16〜v3.7.31 / 2026-06 改修)

シフト生成アルゴリズム (`python/scheduler.py`) を「カバレッジぴったり配置 + 希望シフト最大尊重 + **過剰絶対回避**」を主目的に再設計しました。

### 廃止された機能 (v3.7.16〜v3.7.21)
以下の制約・機能はアルゴリズムおよび UI から**完全に削除**されました。マニュアル・問い合わせ対応時に古い説明をしないよう注意。

| 削除機能 (旧名) | 内容 | 後継 |
|----------------|------|------|
| 戦力バランス制約 (POWER_BALANCE) | スタッフのスキル合計を一定に揃える | なし (削除のみ) |
| ピーク帯スキルミックス (PEAK_SKILL) | ピーク時間帯にベテラン優先配置 | なし |
| 連続5日後の疲労インセンティブ (CONSEC_DAYS_FATIGUE) | 5日連勤後の翌日休み誘導 | 労基35条 HARD + 勤務間10時間 |
| 土日ローテーション公平性 (WEEKEND_FAIR) | 土日出勤を全員均等に | 公平性偏差 (10k) で代替 |
| 時間帯分散 (TIMEBAND_IMBALANCE) | 朝/昼/夕の3区分でバランス | カバレッジ制約 (5M/20M) で代替 |
| 管理者常駐 (MIN_MANAGER) | min_manager 人の管理者常駐 | **OPEN_CLOSE_NO_EMP** (社員1名以上常駐, 10M) |
| NGペア制約 | 相性悪いスタッフを同時配置しない | UI からも削除 (req_pairs は残存) |
| 人件費×評価ランク最小化 | 時給×時間 + 評価ランクペナルティ | 希望シフト尊重を優先 |
| 月給スタッフ強制出勤ペナルティ | 月給スタッフ未出勤に30,000点ペナルティ | v3.7.28 で弱い形 (30k) で復活 |
| 離職防止ハード制約 | 週1日強制配置 (HARD) | **SOFT 化** (50k ペナルティ) |

### 緩和された制約 (v3.7.18〜v3.7.30)
- **OJT 制約** (新人×メンター帯同): 3M → 500k に弱化
- **min_days_week / min_days_month**: HARD → SOFT 化 (200k → v3.7.29 で **30k** に弱化、希望事項扱い)
- **承認済み出勤希望 (approved)**: HARD → SOFT 化 (v3.7.30。配置時 -10M ボーナス、過剰時は諦め)
- **時給通常コスト**: v3.7.29 で 15k → **5k** に弱化 (希望シフトを通すため)
- **evaluation=="D"** のスタッフは rookie 扱いから除外。OJT メンター帯同制約の対象外。

### 追加された機能 (v3.7.25〜v3.7.27)
- **v3.7.25 需給バランス警告バナー** (スタッフ管理画面): 全員の min_days_month 合計 vs 月間需要を表示し、過剰登録を一目で検知
- **v3.7.26 土日希望時間 自動補完**: 時給制スタッフで土日希望が空欄なら平日希望時間を自動コピー
- **v3.7.27 時間入力 UI 改善**: ドロップダウン → `<input type="time">` で打ち込み可能
- **v3.7.27 過剰配置の根本解決 (第一段階)**: COVERAGE_OVER のペナルティを 4M → 8M に強化

### 過剰絶対回避ポリシー (v3.7.28〜v3.7.31)

#### v3.7.28: 過剰絶対回避 + 月給優先 + 時給スポット投入
- **COVERAGE_OVER_DAY**: 5M → **20M** (過剰絶対回避)
- **COVERAGE_OVER_SLOT**: 4M → **20M** (同時刻過剰を絶対に防ぐ)
- **月給スタッフ優先配置**: 月給スタッフが不在のとき 30k ペナルティ (v3.7.21 で削除した強制出勤を弱い形で復活)
- **時給スタッフ控え目配置**: 通常時 15k 追加コスト (v3.7.29 で 5k に弱化)
- **スポット帯時給投入**: time_staff_req で要件が 2 以上のスロットに重なる時間帯はコスト 0 で時給スタッフも積極投入

#### v3.7.29: min_days SOFT 重みと時給コストを大幅弱化
- **min_days_week SOFT ペナルティ**: 200k → **30k** (希望事項扱い)
- **min_days_month SOFT ペナルティ**: 200k → **30k**
- **時給通常コスト**: 15k → **5k** (希望シフトを通すため)

#### v3.7.30: 承認済み出勤希望を HARD → SOFT 化
- 旧: `prob += x == 1` (絶対配置)
- 新: 配置時 **-10M ボーナス** (SOFT)
- 過剰になる場合 (COVERAGE_OVER 20M) は希望を諦める設計

#### v3.7.31: Greedy フォールバックの過剰回避を厳格化
- 旧: `if len(day_shifts) > max_slot_req_day + 2` (過剰許容)
- 新: `if len(day_shifts) >= max_slot_req_day` (ぴったり停止)
- MILP がタイムアウトして Greedy にフォールバックしても過剰を阻止
