## 1. サービス概要

**ラクシフトAI** は、飲食・小売店舗向けのAIシフト自動生成SaaS。

- **Python数理最適化(PuLP)** でベースシフトを生成
- **Gemini AI** が労働基準法チェック・最終調整
- マルチテナント対応（1契約ID = 1店舗）
- Stripe決済によるサブスクリプション課金

**URL:**
- 本体: https://rakushift-ai.pages.dev
- 管理画面: https://rakushift-ai.pages.dev/admin
- GitHub: https://github.com/mochikuro00/rakushift-ai

## 10. AIシフト生成の仕組み

### フロー
```
「AIシフト作成」ボタン
  ↓
1. loadData() — 最新データ取得
  ↓
2. /check — 人員充足チェック（不足時は警告→強行 or 中止）
  ↓
3. 既存シフト削除（リセットモード時）
  ↓
4. /generate — Python PuLP数理最適化 → Gemini AI監査
  ↓
5. シフト保存（Supabase REST API）
  ↓
6. AI診断（裏で実行、モーダルなし）
  ↓
7. ローディング完了 → カレンダー表示
```

### 制約（3段階）

**Tier 1: 法定（絶対遵守）**
- 1日8時間以内（労基法32条）
- 週40時間以内（労基法32条）
- 6h超→45分休憩、8h超→60分休憩（労基法34条）
- 連続6日まで、週1日休日（労基法35条）

**Tier 2: 店舗ルール**
- 最低人員（平日/土日/祝日、時間帯別）
- 管理者常駐
- 定休日・臨時休業

**Tier 3: 最適化**
- チーム戦力バランス（評価A〜Dのスコア）
- 新人にメンター配置（OJT制約）
- コスト最小化
- 勤務日数の均等配分

**制約が解けない場合:** Tier3緩和 → Tier2緩和 → 貪欲法フォールバック

## 11. Stripe決済フロー

### 新規申込
```
お客様が申込フォーム入力（事業者名・担当者名・メール・電話・住所・プラン）
  ↓
/stripe/new-subscription → Stripeチェックアウトセッション作成
  ↓
Stripe決済画面でカード入力
  ↓
決済完了 → Stripe Webhook (checkout.session.completed)
  ↓
自動処理:
  1. create_tenant RPC → テナント作成（契約ID自動生成）
  2. config更新（Stripe情報＋顧客情報保存）
  3. ※メール送信は運営が管理画面から手動トリガー
```

### 運営が決済確認後メール送信
```
管理画面のテナント一覧 →「案内送信」ボタン
  ↓
/admin/send-welcome-email → ウェルカムメール送信
（契約ID、パスワード、ログインURL、プラン名を含む）
```

### プラン変更
- **Stripeポータル経由:** webhook `customer.subscription.updated` → price_idからプラン逆引き → DB更新
- **管理画面経由:** テナント一覧のセレクトボックスで即変更

### 決済失敗時
1. `invoice.payment_failed` → `subscription_status = past_due` + `payment_failed_at` 記録
2. 顧客画面にオレンジバナー「決済エラー」＋Stripeポータルへの再決済ボタン
3. **21日間未対応 → 自動ライセンス停止**（`suspend_license` RPC実行）
4. Stripe側のSmart Retriesで自動再決済（1日後、3日後、5日後）

## 13. ライセンス管理

### ステータスフロー
```
active（通常利用）
  ↓ 解約 or 21日間決済未対応
suspended（停止 → ログイン不可）
  ↓ 6ヶ月経過
data_deletion_scheduled（データ削除対象）
  ↓ 管理者が手動削除
完全削除
```

### データ保持ルール
- 解約後もデータは **6ヶ月間保持**
- プラン変更ではデータは一切削除しない
- 停止中もデータは残る（復活可能）
- 完全削除は管理者が手動で実行（CASCADE）

## 17. 運用ルール・ビジネスロジック

### 役職と評価

**役職:**
| 役職 | 説明 | シフト生成への影響 |
|------|------|-----------------|
| Manager（店長） | 最高権限 | 毎営業日に最低1名配置必須、メンター役 |
| Leader（リーダー） | 副管理者 | メンター役（店長と同等） |
| Staff（スタッフ） | 一般 | 通常配置 |
| Rookie（新人） | 研修中 | メンター必須（単独配置不可） |

**評価:**
| 評価 | 戦力スコア | 影響 |
|------|----------|------|
| A | 3.0 | 優先配置、ペナルティなし |
| B | 2.0 | 通常配置 |
| C | 1.0 | やや控えめ |
| D | 0.5 | メンター必須、高ペナルティ |

### 権限

**管理者（admin）:**
AIシフト作成、シフト編集、スタッフ管理、休み希望承認/却下、設定変更、分析、マニュアル閲覧

**スタッフ:**
自分のシフト確認、休み希望提出、お店のルール確認

### 休み希望フロー
1. スタッフがカレンダーから複数日選択→提出
2. 管理者が承認/却下
3. 承認された日はAIシフト作成時に自動で配置除外

### 決済→サービス開始の流れ
1. お客様が申込フォームで情報入力＋Stripe決済
2. 決済完了→webhook→テナント自動作成
3. 運営が管理画面で決済確認→「案内送信」で契約ID・パスワードをメール
4. お客様がログイン→サービス利用開始
