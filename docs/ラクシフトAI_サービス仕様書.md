## 1. サービス概要

### 1.1 サービス名

**ラクシフトAI**（RakuShift AI）

### 1.2 サービスコンセプト

飲食店・小売店向けのAI搭載シフト管理システム。数理最適化とAI（Google Gemini / OpenAI）を組み合わせ、スタッフの希望・店舗ルール・人員要件を考慮した最適なシフト表を自動生成します。

### 1.3 対象ユーザー

| ユーザー種別 | 説明 |
|---|---|
| 店舗管理者（マネージャー） | シフト作成・承認・スタッフ管理・店舗設定を行う |
| 一般スタッフ | シフト確認・希望休/出勤希望の提出を行う |

### 1.4 提供価値

- シフト作成業務の大幅な時間短縮（手作業 → AI自動生成）
- 労働基準法・店舗ルールに準拠したシフト自動チェック
- スタッフの希望を最大限考慮した公平なシフト配置
- 人件費の可視化・最適化
- マルチテナント対応によるSaaS提供

## 5. AI自動シフト生成エンジン

### 5.1 2段階生成プロセス

```
入力データ          数理最適化           AI監査            出力
(スタッフ/設定)  →  (PuLP MILP)    →   (Gemini API)  →  最適シフト表
                    ↓ 失敗時
                  簡易化 → 貪欲法
```

### 5.2 第1段階：数理最適化（PuLP）

混合整数線形計画法（MILP）による最適化を実施します。

**決定変数：**
- `x[スタッフ, 日付, シフトパターン] ∈ {0, 1}`（バイナリ変数）

**制約条件（ハード制約）：**

| 制約 | 説明 |
|---|---|
| 1日1シフト | 各スタッフは1日に最大1シフトのみ |
| 週あたり最大勤務日数 | スタッフごとの上限遵守 |
| 出勤不可日除外 | 希望休・承認済み休暇日は割当対象外 |
| 連続勤務 | 分割シフト禁止 |

**最適化目標（3段階優先度）：**

| 優先度 | 内容 |
|---|---|
| Tier 1（必須） | 最低人数の充足（平日/休日/祝日） |
| Tier 2（重要） | マネージャー配置、OJTペアリング（メンター ≥ ルーキー） |
| Tier 3（推奨） | 戦力バランス（A評価優先）、人件費最小化 |

**フォールバック機構：**

```
全制約(Tier3) → 簡易化(Tier2) → 最低限(Tier1) → 貪欲法アルゴリズム
```

- ソルバー：CBC（Coin-or Branch and Cut）
- タイムアウト：120秒

### 5.3 第2段階：AI監査（Gemini API）

| 項目 | 内容 |
|---|---|
| 入力 | 第1段階の生成結果（JSON） |
| 処理 | LLMによる制約違反の検出・修正 |
| 温度設定 | 0.2（決定的・正確性重視） |
| 出力 | 修正済みシフト表（JSON配列） |
| 対応モデル | gemini-1.5-flash（推奨）、gpt-4o（代替） |

### 5.4 実行不可能時の対応

スタッフ不足等でシフト生成が困難な場合：

1. システムが人員不足を検知・通知
2. 管理者に「強制モード」の選択肢を提示
3. 強制モード選択時 → 個人制限を緩和して最大限カバー

### 5.5 休憩時間の自動計算

店舗設定の休憩ルールに基づき自動計算：

| 勤務時間 | 休憩時間（例） |
|---|---|
| 6時間以上 | 45分 |
| 8時間以上 | 60分 |

### 6.2 データ分離

- 全テーブルに `organization_id` カラムを保持
- Row Level Security（RLS）により組織単位でデータを完全分離
- テナント間のデータアクセスは不可能

## 7. 認証・セキュリティ

### 7.1 2段階ログインシステム

```
第1段階：店舗ログイン          第2段階：管理者ログイン
(全スタッフ共通)              (管理者のみ)

契約ID + 店舗パスワード   →    管理者ID + 管理者パスワード
       ↓                              ↓
シフト閲覧・申請提出          シフト編集・スタッフ管理・設定変更
```

### 7.2 セキュリティ対策

| 対策 | 内容 |
|---|---|
| パスワード保護 | bcryptハッシュ化（pgcrypto拡張使用） |
| データ分離 | RLS（Row Level Security）によるテナント分離 |
| APIキー保護 | サーバーサイドのみでの取得（フロントエンドに非公開） |
| 設定テーブル保護 | RPC関数経由のみアクセス可（SECURITY DEFINER） |
| 平文パスワード | 一切保存しない |

### 7.3 権限マトリクス

| 機能 | 一般スタッフ | 管理者 |
|---|---|---|
| シフト閲覧 | O | O |

- **リアルタイム更新：** データ変更時の即座のUI反映

## 10. 主要業務フロー

### 10.1 新規店舗セットアップ

```
1. テナント作成（契約ID・パスワード設定）
2. 管理者ログイン
3. 店舗設定（営業時間・定休日・人数ルール）
4. 役職・シフトパターン定義
5. スタッフ登録
6. AI APIキー設定
7. テストシフト生成で動作確認
```

### 10.2 月次シフト作成フロー

```
1. 前月の分析レビュー
2. スタッフの希望休・出勤希望を確認
3.「自動作成」→ 対象期間を選択
4. 人員不足の場合 → 強制モード or スタッフ調整
5. 生成されたシフトを確認（テーブル表示）
6. 必要に応じて手動調整
7. 未処理の申請を承認/却下
8. スタッフへ公開
```

### 10.3 希望休の承認フロー

```
1. スタッフが希望休を提出
2. 管理者の「申請管理」画面に表示
3. 管理者が「承認」をクリック
4. 該当日がスタッフの出勤不可日に自動追加
5. 次回のシフト自動生成時に自動除外
```
