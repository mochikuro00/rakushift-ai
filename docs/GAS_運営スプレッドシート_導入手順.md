# 運営管理スプレッドシート（GAS）導入・運用手順 — v3.7.288

顧客・お問い合わせ・請求／入金・入金明細・返金・解約・紹介者（代理店）フィー・突合を
**1つのスプレッドシートで管理**するための手順です。

顧客リストは手入力せず、必ずシステム（Supabase / Railway API）から取得します。

> **運営が日々読むのは、スプレッドシート内の「📖 使い方」シートです。**
> このファイルは導入・保守する人向けです。

---

## 0. 全体像

```
Supabase (DB)  ←→  Railway (API)  ←→  Apps Script (このスプレッドシート)
   正となるデータ      x-gas-key 認証        運営の作業画面
```

- **同期** = システム → シート（シートは毎回作り直されます）
- **反映** = シート → システム（編集した行だけが送られます）

シートを編集しただけではシステムに入りません。**必ず「反映」のメニューまで実行**します。
未反映の編集は同期で消えないよう黄色で残ります（v3.7.287〜）。

## 1. システム側の準備

### 1-1. マイグレーション適用

`supabase/migrations/` を番号順に適用します。請求まわりは **87〜100** です。

| No | 内容 |
|---|---|
| 87 | 請求書台帳 `invoices` / 代理店フィー / `v_customer_ledger` |
| 88 | 契約日基準（応当日）の請求サイクル |
| 89 | 返金 `refunds` / 解約者 `cancellations` 台帳 |
| 90 | 手動発行テナントの請求情報（会社名・請求先メール・請求開始日・支払サイト） |
| 91 | 解約日の安定化（1顧客1行） |
| 92 | 入金明細 `bank_transactions` と自動消込 |
| 93 | 振込名義の照合・学習 |
| 94 | 分割入金の加算（`add_invoice_payment`） |
| 95 | 取引識別子 `ref` |
| 96 | 最古の請求への充当 |
| 97 | 合同会社の名義正規化 |
| 98 | 入金の按分・指紋の修正 |
| 99 | 解約からの復帰 |
| 100 | **null-role による認証バイパスの修正（重要）** |

適用状況は `supabase/migrations/` の各ファイルが作るオブジェクトの有無で判定できます。
確認クエリは 9 章のトラブルシューティングに載せています。

> **100 は必ず最後に流してください。** 72 は「実行時点に存在した関数」しか直せないため、
> 関数を追加したあとに 100 を通すのが安全側です。100 は冪等で、何度流しても害はありません。

### 1-2. GAS 連携用 APIキーの発行

運営管理画面の **「APIキー・プラットフォーム設定」→「GAS連携キー」** で発行します。
**その場で1度だけ表示**されるのでコピーしてください。

> このキーがあれば顧客の請求情報を読み書きできます。共有範囲は運営管理者のみに限定してください。

### 1-3. Railway の再デプロイ

`python/main.py` を更新したら再デプロイします。反映確認は次のとおりです。

```
POST https://<your-api>/gas/payments/match
  403 → 新コード（ルートは存在し、GASキーが無いだけ）
  404 → 旧コード（未デプロイ）
```

主なエンドポイント（すべて `x-gas-key` 認証）:

| エンドポイント | 用途 |
|---|---|
| `GET /gas/export` | シート同期用の一括エクスポート |
| `POST /gas/invoices/generate` | 応当日を迎えた請求書の生成 |
| `POST /gas/invoices/payments` | 入金消込の書き戻し（置き換え） |
| `POST /gas/invoices/mark-drafted` / `mark-sent` / `mark-reminded` | 下書き・送信・督促の記録 |
| `GET /gas/invoices/overdue` | 督促対象の抽出 |
| `POST /gas/payments/import` | 銀行明細の取込 |
| `POST /gas/payments/match` | 入金の自動照合 |
| `POST /gas/payments/assign` | 要確認の入金を手で紐付け |
| `POST /gas/customers/agency` | 顧客設定の書き戻し |

記録系（`mark-*`）は 1件ずつ呼ばれるため 200/分の上限にしてあります。
まとめて記録すると、実行時間切れで「送ったのに記録されていない」請求書が残り、翌朝再送されるためです。

## 2. Apps Script への反映

### 方法A：clasp（推奨・一括）

```
npm install -g @google/clasp
clasp login
```

`clasp login` はスプレッドシートの**所有アカウント**で承認します。
事前に <https://script.google.com/home/usersettings> で
**Google Apps Script API を ON**（アカウントごとの設定）。

リポジトリ直下の `.clasp.json`:

```json
{
  "scriptId": "<Apps Script のスクリプトID>",
  "rootDir": "gas"
}
```

```
clasp push --force
```

> `clasp push` は**ローカルに無いファイルをリモートから削除**します。
> 旧構成（全部入りの `コード.gs` 1本）から移行する場合、それが消えるのは正しい挙動です。
> 残すと関数が二重定義になります。心配なら先に `clasp pull` で退避してください。

### 方法B：手動

**拡張機能 → Apps Script** を開き、`gas/` の各ファイルを同名で貼り付けます。
`appsscript.json` は **⚙️ プロジェクトの設定 → 「マニフェスト ファイルをエディタで表示する」** を
有効にしてから置き換えます。

### ファイル構成

| ファイル | 役割 |
|---|---|
| `00_Config.gs` | 設定・APIクライアント・シート書き込み・共通ユーティリティ |
| `01_Menu.gs` | カスタムメニュー・APIキー登録・シート初期化 |
| `02_Sync.gs` | システム → シートの全同期 |
| `03_Push.gs` | シート → システムの書き戻し・**未反映編集の退避／復元** |
| `04_Invoice.gs` | 請求書の生成・PDF・Gmail下書き／送信 |
| `05_Reconcile.gs` | お問い合わせ × 顧客の突合 |
| `06_Triggers.gs` | 時間主導トリガー（毎朝・毎月1日）とダイジェスト通知 |
| `07_AutoPayment.gs` | 入金明細の取込・自動消込・督促 |
| `08_Guide.gs` | 「📖 使い方」シートの生成 |
| `appsscript.json` | タイムゾーンと OAuth スコープ（**8個**） |

> スコープは Gmail（下書き・送信）・Drive（読み取り）・ScriptApp（トリガー）を含みます。
> 更新後の初回実行時に**再承認**が必要です。

### 反映後の確認

1. スプレッドシートを再読み込み（`F5`）
2. メニュー「ラクシフト運営」に **「📖 使い方を開く」** が出る
3. 「📖 使い方を開く」→ 承認 → 使い方シートが表示される

## 3. 初期設定

1. メニュー **⚙️ 初期設定（APIキー登録）** — 1-2 のキーを登録（スクリプトのプロパティに保存。シートには書きません）
2. メニュー **🧱 シートを初期化**
3. メニュー **🔄 全データを同期**
4. **⚙️設定** シートを記入（自社名・郵便番号・住所・電話・インボイス登録番号・振込先・通知先メール）
5. メニュー **🧪 テスト請求書を下書きに作成（自分宛）** で PDF の見た目を確認
6. メニュー **⏰ 自動実行をONにする**

### 色の意味

| 色 | 意味 |
|---|---|
| 緑 | 編集してよい列 |
| 黄 | **システムへ未反映の編集**（反映メニューの実行が必要） |
| 赤 | 情報不足で請求書が作れない（請求先メール未登録・プラン未設定） |

## 5. 自動実行

**⏰ 自動実行をONにする** で時間主導トリガーを登録します。

| タイミング | 処理 |
|---|---|
| 毎朝 7時台 | 同期 → 応当日の請求書生成 → Gmail下書き → 入金の自動消込 → 督促 → 突合 |
| 毎月1日 8時台 | 前月の売上・代理店フィー・返金・解約の実績を通知 |

要対応がある日だけ、通知先メールへ**1通のダイジェスト**が届きます。

### 人の手を残している操作

- **請求書メールの送信** — 既定は下書きまで。誤請求は取り返しがつかないため
- **要確認の入金の紐付け** — 判断が割れるものだけ人に回ります
- **代理店設定の変更** — 契約条件の判断が必要

⚙️設定「請求書を自動送信する」を「はい」にすると送信まで自動になります。
運用が安定するまでは「いいえ」を推奨します。

## 6. 請求サイクル（v3.7.286〜）

**暦月一括ではなく、契約日からの応当日**で請求します。

```
請求開始日 8/15  →  8/15〜9/14, 9/15〜10/14, ...
```

- 支払期限 = 発行日 + 支払サイト（既定10日）
- 請求書番号はランダム（連番だと発行件数が外部から推測できるため）
- **過去に遡って請求書は作られません**（現在の請求期間のみ）
- 月末契約（5/31 など）は「5/31 + 1ヶ月 = 6/30」として扱い、取りこぼしません

請求開始日は「顧客管理」シートの **請求開始日** で顧客ごとに変更できます。

## 7. 入金の自動消込

### 取込経路（設定した経路だけが動きます）

| 経路 | 設定 |
|---|---|
| A. 「入金貼付」シートに貼る | 不要（貼るだけ） |
| B. 入金通知メールの本文を解析 | ⚙️設定「入金通知メールの検索条件」 |
| C. 明細CSVがメール添付で届く | ⚙️設定「明細CSVメールの検索条件」 |
| D. Driveフォルダに置かれたCSV | ⚙️設定「明細CSVのDriveフォルダID」 |

同じ明細を二重に取り込まないよう、`日付＋金額＋名義＋摘要＋識別子` の指紋で判定します。
識別子は銀行CSVの残高・取引番号、メールはメッセージID、DriveはファイルIDを使います。
識別子を持たない明細には「その取込の中で何本目か」を振るため、同じCSVを貼り直しても増えません。

### 消込の判定順

1. 名義から顧客が1社に決まり、**残額がぴったり一致**する請求 → その請求に充当
2. 顧客は決まるが金額が一致しない → **古い請求から順に、残額を上限として按分**
3. 名義では決まらないが、同額の未入金が**1件だけ** → その請求に充当
4. どれにも当てはまらない → **⚠ 要確認**として残す

請求額を超えた分はどの請求にも充てず「前受け」として記録だけ残します
（押し込むと過入金になるため）。件数は毎朝の通知に出ます。

### 要確認の解消

「入金明細」シートの⚠行の **照合先請求番号** に請求番号を入れ、
メニュー **💰 入金を手動で反映（消込）** を実行します。
放置すると自動照合の対象から外れたまま残ります。

紐付けた名義は顧客に**自動で学習**され、次回から自動で当たります。
「顧客管理」の **振込名義** 列で事前登録もできます（複数は " / " 区切り）。
この列を**空にして反映すると登録名義が全消し**になります。誤学習した名義を消す唯一の手段です。

## 8. 代理店（紹介者）フィー

顧客ごとの設定が優先され、`紹介者マスタ準拠` のときだけ紹介者マスタの条件が使われます。

| 代理店フィー種別 | 計算 |
|---|---|
| 紹介者マスタ準拠 | 紹介者マスタの報酬タイプ（料率 or 固定額） |
| 固定額 | 「代理店フィー額」をそのまま毎月計上 |
| 料率(%) | 月額 × 「代理店フィー額」% |
| 対象外 | 0円 |

- 紹介者コードが空の顧客はフィー 0円
- 代理店を**外す**ときは「紹介者コード」を**空欄にして反映**
- **請求書を生成した時点のフィーが確定保存**され、後から条件を変えても過去分は動きません
- 「代理店フィー」シートの **支払対象(入金済)** が実際に支払う金額
- 紹介者マスタに無いコードは反映時にエラーになります（集計から消えるのを防ぐため）

## 9. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「APIキーが拒否されました」 | 管理画面で再発行したキーと不一致。1-2 → 3-1 をやり直す |
| メニューが増えない | スプレッドシートを `F5` で再読み込み。Apps Script 側で保存できているか確認 |
| 「承認が必要です」から進めない | 「詳細」→「（プロジェクト名）に移動」→「許可」 |
| 編集が反映されない | 反映メニューを未実行。**黄色いセル**が未反映の印 |
| 請求書が0件 | プラン未設定／請求開始日が未来／既に同期間の請求がある。**赤いセル**が目印 |
| 下書きが作られない | 請求先メールが未登録。顧客管理で登録して反映 |
| 入金明細の見出しを判別できない | 銀行CSVを**見出しごと**貼る。または上の見出しに合わせてデータだけ貼る |
| `clasp push` が permission エラー | Apps Script API が OFF／アカウント違い。`clasp show-authorized-user` で確認 |
| 「変更された行がありません」 | 同期直後の値と同じ。緑の列を編集してから実行 |

### マイグレーションの適用状況を確認する

Supabase の SQL Editor で実行します。`false` があれば未適用です。

```sql
WITH fn AS (
  SELECT p.proname, pg_get_functiondef(p.oid) AS def
    FROM pg_proc p JOIN pg_namespace ns ON ns.oid = p.pronamespace
   WHERE ns.nspname = 'public' AND p.prokind = 'f'
)
SELECT
  (to_regclass('public.invoices')          IS NOT NULL) AS "87",
  (to_regclass('public.refunds')           IS NOT NULL) AS "89",
  (to_regclass('public.bank_transactions') IS NOT NULL) AS "92",
  EXISTS (SELECT 1 FROM fn WHERE proname = 'payer_matched_invoices') AS "98",
  NOT EXISTS (SELECT 1 FROM fn WHERE def ~ 'v_role\s+NOT\s+IN\s*\(') AS "100";
```

## 10. 触ってはいけないもの

- **列名・シート名** — 同期はこれを目印に場所を探します。不要な列は「非表示」に
- **`_同期スナップショット` シート** — 編集検出の内部データ。消すと未反映の編集を拾えなくなります
- **APIキー** — 顧客情報と請求データにアクセスできます
