# 運営管理スプレッドシート（GAS）導入手順 — v3.7.285

顧客・お問い合わせ・売上（請求／入金）・紹介者（代理店）・代理店フィー・突合を
**1つのスプレッドシートで管理**するための導入手順です。

顧客リストは手入力せず、必ずシステム（Supabase / Railway API）から取得します。

---

## 1. 何が解決されるか

| 課題 | 対応 |
|---|---|
| 運営管理者の**請求書ベースの入金履歴が顧客に紐づかない** | `invoices` 台帳を新設。請求書払い・OEM の請求と入金を顧客(`config`)に紐付け、決済管理タブとスプレッドシートの両方で確認可能に |
| お問い合わせフォームと顧客リストの**抜け**が分からない | `reconcile_inquiries()` でメール→電話→会社名の順に照合し、「未契約の問い合わせ」「問い合わせ記録なしの顧客」「紹介者コード不一致」を検出 |
| **紹介者（代理店）フィーの最終計算**が手作業 | 顧客ごとにフィーを上書き設定でき、請求書発行時にフィーを確定。入金済みのみを「支払対象」として月次集計 |
| Stripe 決済前の見込み客がシートに残らない | お問い合わせは**全件・全カラム**をシートへ同期（フォーム項目が増えても列が自動追加） |

## 2. システム側の準備

### 2-1. マイグレーション適用

```
supabase/migrations/20260809000000_87_billing_ledger_and_agency.sql
```

Supabase の SQL Editor に貼り付けて実行、または `supabase db push` で適用します。

作成されるもの:

- `invoices` テーブル（請求書 + 入金台帳）
- `config` に `agency_fee_type` / `agency_fee_amount` / `billing_email` / `payment_terms_days` / `billing_note`
- `v_customer_ledger` ビュー（顧客台帳）
- 関数: `generate_monthly_invoices` / `record_invoice_payment` / `update_customer_agency` / `reconcile_inquiries` / `list_agency_fees` / `resolve_agency_fee` / `get_plan_price`

### 2-2. GAS 連携用 APIキーの発行

運営管理画面の **「APIキー・プラットフォーム設定」→「GAS（運営管理スプレッドシート）連携キー」**
で「キーを発行 / 再発行」を押します。生成されたキーは**その場で1度だけ表示**されるので、
コピーして 3-6 の手順で Apps Script に登録してください。

> - このキーを知っていれば顧客の請求情報を読み書きできます。共有範囲は運営管理者のみに限定してください。
> - 再発行すると古いキーは無効になり、Apps Script 側の再登録が必要です。
> - 手作業で設定したい場合は `platform_settings.gas_api_key` を直接更新しても構いません（16文字以上）。

## 3. スプレッドシートの作成

1. Google スプレッドシートを新規作成（名前例: `ラクシフトAI 運営管理`）
2. **拡張機能 → Apps Script** を開く
3. `gas/` 配下のファイルをすべてコピーして、同じファイル名でスクリプトに貼り付ける

   | スクリプトファイル | 役割 |
   |---|---|
   | `00_Config.gs` | 設定・APIクライアント・シート書き込み |
   | `01_Menu.gs` | カスタムメニュー・APIキー登録 |
   | `02_Sync.gs` | システム → シートの全同期 |
   | `03_Push.gs` | シート → システムの書き戻し（入金・代理店設定） |
   | `04_Invoice.gs` | 請求書の一括生成・PDF・Gmail下書き |
   | `05_Reconcile.gs` | お問い合わせ × 顧客の突合 |

4. **プロジェクトの設定 → 「appsscript.json」マニフェストを表示** を有効にし、`gas/appsscript.json` の内容で置き換える
5. スプレッドシートを開き直す（メニュー「**ラクシフト運営**」が出る）
6. メニュー → **⚙️ 初期設定（APIキー登録）** で 2-2 のキーを登録
   （キーはスプレッドシートではなくスクリプトのプロパティに保存されます）
7. メニュー → **🧱 シートを初期化** → **🔄 全データを同期**

## 4. シート構成

| シート | 内容 | 編集 |
|---|---|---|
| ⚙️設定 | 対象月・自社情報・振込先・メール文面 | ✅ |
| 顧客管理 | 契約ID/店舗/プラン/請求区分/**代理店・代理店フィー**/入金状況 | 緑色の列のみ ✅ |
| お問い合わせ | フォーム全項目（全件）＋契約済み判定 | 参照のみ |
| 請求・入金 | 請求書ごとの請求額・**入金日/入金額/入金方法/振込名義** | 緑色の列のみ ✅ |
| Stripe決済 | Stripe の決済履歴 | 参照のみ |
| 紹介者マスタ | 代理店の報酬条件・振込口座・紹介実績 | 参照のみ |
| 代理店フィー | 対象月のフィー確定額（支払対象 / 保留） | 参照のみ |
| 突合チェック | 未契約の問い合わせ・問い合わせ記録なしの顧客・紹介者不一致 | 参照のみ |
| 売上サマリー | 月次の請求／入金／未入金／フィー | 参照のみ |

> **緑色のヘッダー = 編集してよい列**です。編集後にメニューから書き戻すと、システムが正となり次の同期でシートに反映されます。
> シートは同期のたびに上書きされるため、**書き戻す前に同期しない**でください。

## 5. 毎月の運用フロー

```
① メニュー「🔄 全データを同期」
        ↓
② 顧客管理シートで代理店（紹介者コード・フィー種別・フィー額）を確認・修正
   → 「🏢 代理店設定をシステムに反映」
        ↓
③ 「🧾 対象月の請求書を一括生成」
   （請求書払い・OEM の稼働中テナントが対象。同月の重複生成なし）
        ↓
④ 「📧 未送付の請求書をGmail下書きに作成」
   → Gmail の下書きを確認して送信
        ↓
⑤ 入金を確認したら 請求・入金シートに「入金日」「入金額」「振込名義」を入力
   → 「💰 入金をシステムに反映（消込）」
        ↓
⑥ 「代理店フィー」シートで支払対象（入金済み分）を確認して代理店へ支払い
        ↓
⑦ 「✅ 突合チェック」で対応漏れ・紹介者の付け漏れを確認
```

対象月を変えたいときは **⚙️設定シートの「対象月」** に `2026-08` のように入力します（空欄なら今月）。

## 6. 代理店（紹介者）フィーの決まり方

顧客ごとの設定が優先され、`紹介者マスタ準拠` のときだけ紹介者マスタの条件が使われます。

| 顧客管理シートの「代理店フィー種別」 | 計算 |
|---|---|
| 紹介者マスタ準拠 | 紹介者マスタの報酬タイプ（料率 or 固定額）で計算 |
| 固定額 | 「代理店フィー額」をそのまま毎月計上 |
| 料率(%) | 月額 × 「代理店フィー額」% |
| 対象外 | 0円（この顧客は報酬対象外） |

- 紹介者コードが空の顧客はフィー 0円です。
- 代理店を**外す**ときは、顧客管理シートの「紹介者コード」を**空欄にして書き戻し**ます。
- **請求書を生成した時点のフィーが請求書に確定保存**されます。後から条件を変えても過去分は動きません。
- 「代理店フィー」シートの **支払対象(入金済)** が実際に支払う金額、**保留(未入金)** は入金待ちです。
- 紹介者マスタに存在しないコードは書き戻し時にエラーになります（集計から消えるのを防ぐため）。

## 7. 請求書とメール下書き

- PDF は Apps Script 側で生成します（適格請求書の記載事項：発行者名・登録番号・対象月・10%対象額・消費税額）
- 宛先は顧客の**請求先メール**。未登録の顧客はスキップされ、結果ダイアログに一覧表示されます
- 件名・本文は ⚙️設定シートで変更できます。差し込みタグ: `{対象月}` `{顧客名}` `{請求番号}` `{金額}` `{支払期限}`
- 下書きを作成した請求書にはシステム側で印が付き、**同じ請求書の下書きが二重に作られることはありません**
- 送信はあくまで運営が Gmail で内容を確認してから行います（自動送信はしません）

## 8. 運営コンソール（admin.html）側

**決済管理タブ**の下部に「請求書払い・OEM の請求／入金履歴」が追加されています。

- 対象月を選んで請求一覧を表示（請求額・入金額・状態・代理店フィー）
- 「入金記録」ボタンから入金日・入金額・入金方法・振込名義を登録
- 期日超過の未入金は赤く表示
- 「対象月の請求書を一括生成」も管理画面から実行可能

スプレッドシートと管理画面のどちらから入金を記録しても、同じ `invoices` 台帳が更新されます。

## 9. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「APIキーが拒否されました」 | 管理画面で再発行したキーと Apps Script のキーが不一致。2-2 → 3-6 をやり直す |
| 「APIキーが未設定です」 | メニュー → ⚙️ 初期設定（APIキー登録）を実行 |
| 請求書が0件生成される | 対象がいない（Stripe 契約は対象外）／既に同月分がある／ライセンスが停止中 |
| Stripe決済シートが空 | `platform_settings.stripe_secret_key` が未設定。請求書払いのみの運用なら問題なし |
| 書き戻しで「紹介者コードが未登録です」 | 運営コンソールの紹介者管理でそのコードを先に発行する |
| 「変更された行がありません」 | 同期直後の値と同じ。緑色の列を編集してから実行する |
| 入金を反映しても状態が変わらない | 入金額が請求額未満だと「一部入金」。全額入力で「入金済」になる |
